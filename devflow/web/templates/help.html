How to use devflow

Claude plans and reviews, a cheaper model writes the code, and you approve twice: the plan, then the change. devflow never merges or pushes.

Start a task

  1. Open New task, choose the project and describe the result you want. For a bug, say what happens and what should happen.
  2. Wait for the plan. The task shows in Planning, then in Plan ready with an amber mark when it reaches gate 1.
  3. Open the task, read the Spec, and approve it, or send it back with what to change.
  4. The worker codes in its own git worktree, devflow runs your checks, and Claude reviews the diff.
  5. At gate 2, read the changed files, the review and the checks, then approve. The branch is kept for you to merge.

The list shows the projects in the config file. To add one, open Projects, pick a repository or type the folder of its git checkout, and add it. It is usable at once.

The two gates

Gate 1, the plan. Approve to create the branch and start coding. Send it back to change the plan; the text you write goes to the planner. If the planner asked a question, your answer goes the same way.

Gate 2, the change. Approve to finish the task. Send it back to ask the worker for a fix. If the base branch moved and the change no longer merges cleanly, approval is refused until you use Catch up with base.

Stop task cancels at any stage and keeps the branch.

Ask about code

Ask answers questions about one project or all of them, such as "where is checkout validated?". It only reads. Follow-up questions keep the context of the conversation until devflow restarts.

Models and free tier

Agents and models shows whether Claude Code and opencode are installed, their version, the last run, today's use and any usage limit. The opencode server only runs while a task is coding; "starts when a task reaches coding" is normal.

Planning, review and Ask always use Claude Code. The worker uses the model in the config file, usually through an AI gateway such as OmniRoute that tries several free providers in turn.

Models sends each model one short request and shows which answer now. Rate limited means that provider's free quota is used up for now; the gateway moves on to the next model. When every model is limited, the task is blocked with the reset time.

With free_only = true in [gateway], devflow refuses any worker model that is not a free tier, and checks the models inside each combo before every run. For a guarantee on the account side, set the credit limit of the provider key to 0.

Usage and budgets

Usage shows tokens and reported cost per day, backend, role and model. Free models report no cost, so their budget is in tokens. Budgets in [budget] can warn you, refuse new tasks, or stop running ones.
